# 部署与复现

## 1. 部署拓扑

```text
Android 真机
   │ HTTPS 443 (域名)
   ▼
Nginx ── 80 跳转 443、TLS、限流、请求体限制
   │ HTTP 8080（Docker 内网）
   ▼
Spring Boot 后端 ── JWT / 权限 / 图片流
   │
   ├── MySQL 8.4（Docker volume: mysql_data）
   └── /data/uploads（Docker volume: uploads_data）
```

Nginx 不挂载也不暴露上传目录，`/uploads/` 直接 404；图片只能通过后端鉴权接口读取。

## 2. 服务器前提

- 一台可 SSH 登录的 Linux 服务器（Ubuntu 22.04/24.04 推荐）。
- 已安装 Docker 24+ 与 Docker Compose v2；`docker compose version` 可用。
- 安全组/防火墙开放 80、443；22 仅对管理 IP 开放。
- 域名 A 记录指向服务器公网 IP，DNS 已生效（`dig +short class.example.com`）。
- 至少 2 GB 内存、2 vCPU 和 10 GB 可用磁盘；生产容量应按学生照片量估算。
- 准备好证书：可用 Certbot（standalone）或已有证书；本配置默认读取宿主机 `/etc/letsencrypt`。

本节是具备 80/443 的通用服务器流程；如果反向代理使用其他端口或已有 Caddy，请按实际入口调整。

## 3. 上传代码

```bash
sudo mkdir -p /opt/classroom-pulse
sudo chown "$USER":"$USER" /opt/classroom-pulse
# 将本项目全部文件放到 /opt/classroom-pulse（scp/rsync/git 均可）
cd /opt/classroom-pulse
```

## 4. 配置生产环境变量

```bash
cd /opt/classroom-pulse/deploy
cp .env.example .env
chmod 600 .env
```

生成随机密钥：

```bash
python3 - <<'PY'
import secrets
print("MYSQL_PASSWORD=" + secrets.token_urlsafe(32))
print("MYSQL_ROOT_PASSWORD=" + secrets.token_urlsafe(32))
print("JWT_SECRET=" + secrets.token_urlsafe(64))
print("BOOTSTRAP_TEACHER_PASSWORD=" + secrets.token_urlsafe(18))
PY
```

把输出填写进 `.env`，同时设置：

```dotenv
DOMAIN=class.example.com
MYSQL_DATABASE=classroom_pulse
MYSQL_USER=classpulse
BOOTSTRAP_TEACHER_USERNAME=admin
BOOTSTRAP_TEACHER_NAME=教师
BOOTSTRAP_ADMIN_USERNAME=admin
BOOTSTRAP_ADMIN_PASSWORD=
BOOTSTRAP_ADMIN_NAME=系统管理员
ADMIN_SESSION_HOURS=8
CORS_ALLOWED_ORIGINS=
```

说明：

- **首个教师账号**：设置 `BOOTSTRAP_TEACHER_USERNAME` / `BOOTSTRAP_TEACHER_PASSWORD` / `BOOTSTRAP_TEACHER_NAME`，首次启动会创建一个教师账号；创建成功后立即从 `.env` 删除 `BOOTSTRAP_TEACHER_PASSWORD` 并重启。教师自助注册始终不开放。
- `JWT_SECRET` 至少 32 字节；`prod` profile 缺失会直接启动失败，这是刻意设计。
- `.env` 已被 `.gitignore` 忽略，权限 600，不可提交。

## 5. 申请 HTTPS 证书

在启动 Nginx 之前，用 Certbot standalone 占用 80 端口签发：

```bash
sudo apt-get update
sudo apt-get install -y certbot
sudo certbot certonly --standalone -d class.example.com
```

证书应位于：

```text
/etc/letsencrypt/live/class.example.com/fullchain.pem
/etc/letsencrypt/live/class.example.com/privkey.pem
```

如果已有证书，调整 `deploy/nginx/default.conf.template` 中的路径即可，但建议保持挂载 `/etc/letsencrypt`。

## 6. 启动

```bash
cd /opt/classroom-pulse
chmod +x scripts/deploy.sh scripts/backup.sh
./scripts/deploy.sh
```

`deploy.sh` 会：

1. 检查 `deploy/.env` 与证书文件；
2. `docker compose --env-file .env up -d --build`；
3. 等待 `https://<DOMAIN>/healthz`；
4. 输出容器状态。

手工等价命令：

```bash
cd /opt/classroom-pulse/deploy
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
docker compose --env-file .env logs -f backend
```

首次构建会下载 Gradle/Spring 依赖，耗时取决于服务器网络；数据库启动后 Flyway 自动建表。

## 7. 部署后验证

### 7.1 服务端

```bash
curl -fsS "https://class.example.com/healthz"
curl -fsS "https://class.example.com/actuator/health"   # 应返回 404（Nginx 不暴露）
curl -s -o /dev/null -w "%{http_code}\n" "https://class.example.com/uploads/anything"  # 404

# 教师登录
curl -s -X POST "https://class.example.com/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"<teacher-username>","password":"<password>"}'
```

### 7.2 Android 生产包

```bash
cd android
./gradlew assembleRelease \
  -PCLASSROOM_API_BASE_URL=https://class.example.com/ \
  -PCLASSROOM_KEYSTORE_PATH=/secure/classpulse-release.jks \
  -PCLASSROOM_KEYSTORE_PASSWORD='<keystore-password>' \
  -PCLASSROOM_KEY_ALIAS=classpulse \
  -PCLASSROOM_KEY_PASSWORD='<key-password>'
```

生成签名 release APK：`android/app/build/outputs/apk/release/app-release.apk`。

如果尚未创建 keystore：

```bash
keytool -genkeypair -v \
  -keystore /secure/classpulse-release.jks \
  -alias classpulse \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass '<keystore-password>' -keypass '<key-password>' \
  -dname "CN=Classroom Pulse, OU=Teaching, O=Your University, L=City, ST=Province, C=CN"
```

将 APK 安装到 Android 8.0+ 真机。Production release 隐藏服务器地址和“服务器设置”入口，使用构建时传入的 HTTPS 地址；Debug 包保留开发用服务器设置。主清单禁止明文 HTTP。

管理后台使用同一域名下的 `/admin`。管理员首次密码通过 `BOOTSTRAP_ADMIN_*` 初始化，成功后从 `.env` 删除 `BOOTSTRAP_ADMIN_PASSWORD`。反向代理必须把 `/admin` 和 `/api/admin/*` 转发到后端；仓库内的 Nginx 模板已包含该规则。

### 7.3 数据核对

```bash
curl -s "https://class.example.com/api/v1/courses" \
  -H "Authorization: Bearer <token>"
```

确认教师课程、成员数、签到码、问答和作业统计符合预期。

## 8. 证书续期

```bash
sudo crontab -e
```

加入（每天两次尝试续期）。本方案初次签发使用 standalone，续期时需短暂释放 80 端口：续期前停止 Nginx 容器，续期后重新启动。课堂应用通常在凌晨无人使用，停机窗口只有数秒：

```cron
17 3,15 * * * certbot renew --quiet --standalone --pre-hook "cd /opt/classroom-pulse/deploy && docker compose --env-file .env stop nginx" --post-hook "cd /opt/classroom-pulse/deploy && docker compose --env-file .env start nginx"
```

证书到期前可手动演练一次：

```bash
sudo certbot renew --dry-run --standalone \
  --pre-hook "cd /opt/classroom-pulse/deploy && docker compose --env-file .env stop nginx" \
  --post-hook "cd /opt/classroom-pulse/deploy && docker compose --env-file .env start nginx"
```

## 9. 备份

```bash
cd /opt/classroom-pulse
./scripts/backup.sh
```

输出到 `deploy/backups/<UTC时间>/`：

- `mysql.sql.gz`：数据库结构与数据；
- `uploads.tar.gz`：作业图片；
- 自动保留最近 30 天。

建议 cron 每日执行，并把备份同步到另一台机器/对象存储。备份文件含学生照片和密码哈希，按敏感数据管理。

### 恢复

```bash
cd /opt/classroom-pulse/deploy
# 先停后端，避免写入
docker compose --env-file .env stop backend

# 恢复 MySQL（会覆盖同名表数据）
gunzip -c backups/20261028T120000Z/mysql.sql.gz | \
  docker compose --env-file .env exec -T mysql sh -c 'exec mysql -u root -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'

# 恢复图片
docker compose --env-file .env exec -T backend tar -xzf - -C /data < backups/20261028T120000Z/uploads.tar.gz

docker compose --env-file .env start backend
curl -fsS "https://<DOMAIN>/healthz"
```

数据库与图片要恢复到同一时间点；若图片缺失，API 会返回 `IMAGE_NOT_FOUND`，不会伪造图片。

## 10. 升级与回滚

### 升级

```bash
cd /opt/classroom-pulse
./scripts/backup.sh
# 放入新版本源码
cd deploy
docker compose --env-file .env up -d --build
docker compose --env-file .env logs --tail=100 backend
```

Flyway 会在启动时应用新迁移。生产迁移应向前兼容；禁止直接修改已应用的旧迁移文件。

### 回滚

1. 切回上一个源码版本；
2. 若新版本包含不可逆迁移，先恢复升级前备份的数据库与 `uploads`；
3. `docker compose --env-file .env up -d --build`；
4. 验证健康检查和登录。

## 11. 本地复现（不需要公网）

### 11.1 Docker 一键

```powershell
.\scripts\new-local-env.ps1
docker compose --env-file .env.local -f docker-compose.local.yml up -d --build
Invoke-RestMethod http://127.0.0.1:8080/actuator/health
```

`docker-compose.local.yml` 只启动 MySQL + 后端，后端端口 8080；APK Debug 默认访问 `http://10.0.2.2:8080/`（Android 模拟器映射到宿主机）。

### 11.2 不使用 Docker 的后端

1. MySQL 8.4+ 创建数据库 `classroom_pulse`；
2. 设置环境变量：`DB_URL`、`DB_USER`、`DB_PASSWORD`、`JWT_SECRET`、`UPLOAD_DIR`；
3. `cd backend && ./gradlew bootRun`；
4. 首次启动可设置 `BOOTSTRAP_TEACHER_USERNAME`、`BOOTSTRAP_TEACHER_PASSWORD`、`BOOTSTRAP_TEACHER_NAME` 创建首个教师，随后移除密码变量。

### 11.3 构建 Android

```powershell
cd android
$env:JAVA_HOME = "D:\javajdk"  # JDK 17 或 21
.\gradlew.bat assembleDebug -PCLASSROOM_API_BASE_URL=http://10.0.2.2:8080/
```

真机连接同一局域网时，可改为 `http://<宿主机局域网IP>:8080/`，并在 Debug 包的服务器设置中确认。Debug 包允许明文；生产 release 不允许。

## 13. 常见问题

| 现象 | 排查 |
| --- | --- |
| 后端启动报 JWT_SECRET | prod profile 要求 `JWT_SECRET`，检查 `deploy/.env` 与 `env_file` |
| 后端启动报数据库连接 | 检查 MySQL healthcheck、`DB_PASSWORD` 与数据库名 |
| Nginx 启动失败 | 检查证书路径和 `DOMAIN` 是否与证书目录一致 |
| Android 真机连不上 | 服务器地址必须带 `https://`，release 不允许 HTTP；如果部署端口不是 443，请检查 DNS 与反向代理端口 |
| 图片 401/403 | 令牌是否过期；学生只能看自己的提交，教师只能看自己课程 |
| 邀请码无效 | 教师课程卡可复制，大小写不敏感由服务端大写归一化 |
| 时区显示不一致 | 数据库/服务端为 UTC，客户端按设备时区展示；确认手机时区 |
